# BKH App - Enterprise Portal

Unified enterprise portal for BKH Group. Deployed via Intune Managed Browser - users land
directly on the app with no login screen. Microsoft Entra ID SSO will be added later.

## Stack

| Concern       | Choice                                                    |
| ------------- | --------------------------------------------------------- |
| Framework     | React 18 + Vite, TypeScript (strict)                      |
| Routing       | TanStack Router v1 - file-based (`src/routes`)            |
| Data fetching | TanStack Query v5 - mock resolvers with a 300ms delay     |
| UI            | shadcn/ui (new-york style, zinc base) on Radix primitives |
| Styling       | Tailwind CSS v4                                           |
| Icons         | Lucide React                                              |
| Dates         | date-fns (Australian format `dd/MM/yyyy`)                 |

## Running locally

```bash
npm install
npm run dev       # http://localhost:5173 (opens automatically)
npm run build     # type-check + production build
npm run lint      # oxlint
```

`src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin on dev/build. Do not edit it by hand.

## Theming

Tailwind v4 is configured in CSS, so there is no `tailwind.config.ts`. Brand tokens are in
`src/index.css` under `@theme`:

- `brand` (`#6B46C1`) - primary purple, e.g. `bg-brand`, `text-brand`, plus `brand-50/100/600/700` shades
- shadcn `--primary` is set to the same purple, so default `<Button>` and focus rings use it
- Sidebar uses a light, faintly purple-tinted white (`--sidebar-*` variables)
- zinc - shadcn base neutral

## Adding a new module tile

1. **Add the module** to the `modules` array in `src/data/mock.ts`:

   ```ts
   {
     id: 'plant',
     name: 'Plant & Equipment',
     description: 'Pre-starts and service records',
     color: 'purple',                 // blue | red | green | purple | orange | amber
     icon: 'Truck',                   // lucide icon name
     href: '/plant',
     badge: { label: '2 due', variant: 'default' },   // optional
     requiredRoles: ['PM', 'Supervisor'],             // optional - omit for all roles
   }
   ```

2. **Register the icon** in `src/lib/icons.ts` - import it from `lucide-react` and add it to the
   `icons` map. Unregistered names fall back to `LayoutDashboard`.

3. **Create the route** as `src/routes/plant.tsx`. The router plugin picks it up automatically:

   ```tsx
   import { createFileRoute } from '@tanstack/react-router'
   import { ComingSoon } from '@/components/ComingSoon'

   export const Route = createFileRoute('/plant')({
     staticData: { title: 'Plant & Equipment' }, // shown in the Topbar
     component: () => <ComingSoon title="Plant & Equipment" />,
   })
   ```

4. Optional: add a sidebar entry to `navItems` in `src/data/mock.ts`.

For an **external system** tile, add it to `externalLinks` instead, with `external: true` and the
full URL as `href`. It opens in a new tab and shows the "External" label.

## Role-based access

The current user comes from `MockUserContext` (John Smith, PM). In production the role will come
from Entra ID token claims. `useModules()`, `useNavItems()` and `useExternalLinks()` filter items
by `requiredRoles` against the current role. Scaffolders only see Site Diaries.

For demos, the user menu at the bottom of the sidebar has a dev-only **Preview as role** switcher.
Role filtering only hides UI. Route guards and API authorisation still need to enforce it once auth
is in place.

## Notes

- **Licence photos (Site Crews):** save the photo taken at induction as
  `public/licences/<employee id>/<licence id>.jpg`, e.g. `public/licences/emp-001/white-card.jpg`. Licence ids are
  the licence name in lower-case with dashes (see `buildLicences` in `src/data/employees.ts`). Missing photos show
  an ID-card placeholder.
- **Incident photos and safety alert PDFs:** put incident photos in `public/incidents/` and list their file
  names in the incident's `photos` array in `src/data/safety.ts` (missing files show a placeholder tile).
  Put alert PDFs anywhere in `public/` and set the alert's `pdf` path, e.g. `pdf: 'Safety Alert.pdf'`.
  `sample-1.jpg` to `sample-5.jpg` are low-res crops from an alert email screenshot - replace them with the
  originals.

- **React 18 and shadcn/ui:** the latest shadcn components target React 19, where `ref` is a
  normal prop. `Button`, `DialogOverlay` and `SheetOverlay` in `components/ui` have been wrapped
  in `React.forwardRef` so Radix `asChild` triggers and exit animations work on React 18. If you
  re-add those components with the shadcn CLI, apply the same patch, or upgrade to React 19.
- **Mock data:** October 2026 for Project A (FW-001). Diaries run Monday to Friday, plus Saturday
  Oct 3 and Oct 17. Submitted diaries show as a small icon next to the date; ITPs, lost hours,
  incidents and employees show as badges. Weekend cells are greyed out. Other months return no data.
